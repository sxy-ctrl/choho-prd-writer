# 按需求类型选择写法

类型可以组合；用户已有结构、明确要求和当前事实优先。

| 类型 | 建议组织方式 | 需要展开的关键内容 |
|---|---|---|
| 新系统 0–1 | 背景与边界 → 角色/业务对象 → 流程 → 按模块或端列功能 → 核心规则 → 影响与验收 | 生命周期、操作入口、权限归属、跨系统标识、同步触发、业务类型差异、配置层级 |
| 小型功能优化 | 设计依据 → 按改动点列原行为/新行为 → 相关边界及验收 | 适用端/状态、引用已有结果、兼容、保存与下游影响；不套长篇背景 |
| 规则新增 | 背景 → 按对象列规则 → 优先级/降级 → 例外与验收 | 单位、比较符号、且/或关系、新旧规则替换、候选顺序、无可行结果；用临界值和条件组合验证 |
| 经典新增功能 | 背景目标 → 原型与入口 → 功能列表 → 复杂规则单列 → 影响范围 | 参数、状态、再次进入、保存与重置、对象身份、批量/单项范围、操作记录 |
| 功能重构 | 旧行为问题 → 替换/保留关系 → 新功能 → 存量与输出闭环 | 旧入口隐藏是否影响旧对象、数据继承、报告/导出/术语一致、本期与后续分开 |
| SaaS 流程优化 | 按端/角色/迭代批次分组 → 状态与操作 → 列表/权限 → 通知 → 验收 | 谁在何状态下执行、归属变化、列表去向、通知接收者、下一步入口、配置是否追溯 |

## 细节深度

功能列表承载主要交互。复杂计算、跨步联动、引用关系或对象生命周期，单独写规则并由主表引用，避免全文重复。

参数需说明单位、默认值、范围、精度与输入处理；所有具体数值必须有当前依据。需要坐标或变换时区分绝对值/增量、局部/世界坐标、方向与保存值。

连续或批量对象需说明身份、关联与作用范围；用具体例子解释规则，但不让例子代替规则。历史示例中的阈值、ID 格式或业务状态不自动沿用。

正文、原型、文案、规则表和验收必须一致。对于未完成的句子、TODO、删除线、未决优先级或被裁切表格，保留缺口并列决策，不推定答案。
