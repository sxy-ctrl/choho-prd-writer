# 边界与联动检查

这是推导问题的检查工具，不是预设产品规则。选择需求触发的维度，将结果落到正文、验收或待确认决策；无关项直接略过。不要把检查问题全部抛给用户。

## 从操作推导分支

对主流程中的每个写入、计算、切换或提交操作，问：允许执行的状态是什么？没有对象会怎样？重复执行会怎样？执行中离开会怎样？失败后怎样继续？成功结果影响哪些对象？

| 维度 | 触发信号 | 要补足的规则 |
|---|---|---|
| 角色与权限 | 多端、认领、分配、分享、只读 | 按角色/所属机构/负责人区分查看和写入；无权限入口表现及执行时权限变化；分享页展示不等于可编辑或留言 |
| 状态与入口 | 多节点、加载、提交、退回 | 尚未加载/部分加载/完成/失败时入口是否可用；处理中重复点击；执行期间状态被其他操作改变 |
| 参数和集合 | 输入、滑杆、多选、批量 | 最小/最大/越界、零/负数、精度、空/非法值；无对象、单个、多项、部分项不适用；批量是否部分成功与如何反馈 |
| 编辑生命周期 | 预览、保存、重置、撤销 | 预览是否写入；保存何时成功；未保存离开；重置到算法初值、上次保存还是配置默认；撤销作用域和可恢复数据 |
| 异步计算 | AI、重建、任务队列 | 提交/处理中/成功/失败的可操作项；旧请求晚返回是否覆盖新操作；切换节点后结果归属；超时、刷新、重试如何确认最终状态 |
| 数据作用域 | 病例、阶段、方案、节点 | 写入属于哪个 ID 和层级；复制/重启是否继承；删除后关联展示和数据；不要混淆阶段留言与方案留言 |
| 跨端与上下游 | 医生端、技工端、厂商端、分享、生产 | 各端显示/编辑范围；共享源还是副本；同步何时发生；保存是否使后续节点失效/重算；导出或生产使用哪个版本 |
| 历史兼容 | 新字段、新默认、旧方案 | 无字段与显式零值是否区分；旧方案打开是否变化；既有编辑是否保留；数据迁移和回退行为有无依据 |
| 协作与冲突 | 多人编辑、认领、重新分配 | 同时执行时归属和失败反馈；旧页面提交如何处理新版本；机构隔离；只记录本需求相关规则 |
| 通知与文案 | toast、alert、消息、操作记录 | 成功是否真的完成；谁收到、链接指向哪个对象；失败是否误报成功；变量与当前层级一致；批量记录是否包含正确范围 |

## 3D / 正畸编辑专用

仅在涉及对应功能时检查：
- 全颌/上颌/下颌/单牙、多牙选择，缺牙、拔牙、不可编辑牙是否影响操作集合。
- 初始位、目标位、分步、附件之间的数据来源与重载关系；手工结果在 AI 重新加载后保留、失效还是默认，必须有依据。
- 简单保存与完整保存分别影响什么节点；不把某篇历史 PRD 的选项推广到所有入口。
- 变换参数是绝对值还是增量；是否叠加；单位、坐标系、正负方向；预览数值与保存模型是否一致。
- 分步中关键帧、步数、移动序列、片切、附件的联动范围；只要求重置某项时，不默认清空整个方案。
- 算法不可用、模型缺失、数据不完整时能否继续；医学阈值、运动约束与有效范围由提供的业务依据确认，Agent 不创造医学标准。

## 将问题变为可评审规则

输入：“目标位新增调整功能，保存后其他端同步。”

可确定：目标位有入口，保存结果需要跨端展示。
待确认：其他端具体有哪些？哪些端能编辑？保存是否触发后续分步重算？处理中切换节点如何处理？

写法示例：
- R-01：在目标位提供“调整”入口（按钮位置待确认）。
- R-02：保存成功后其他端展示已保存结果；具体端与同步时机 `【待确认 D-01】`。
- R-03：`【建议，待确认 D-02】` 保存失败时保留当前编辑并提供重试，失败不得显示成功提示。

不要直接填入“200ms 防抖、500ms loading、失败自动重试三次”等貌似完整但没有依据的数值。需要这样的参数时写清待决策问题和选择依据。
