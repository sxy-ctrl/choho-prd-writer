# 格式与来源约定

公开版提供可复用写作流程，不附带内部 PRD。用户在受控工作区提供样例后，提取其标题层级、表格列、术语、交互表达和细节深度；只读取当前需求相关的 1–3 份资料。

## 选择与核对

- 已有稿件的结构优先。完整功能可用背景、流程、功能列表、核心规则、影响范围和原型；小迭代直接按端或改动点组织。
- 功能表可用“模块/功能/需求详情/示意图/备注/优先级”，规则表可用“对象/条件/行为/例外”，按可读性选择列数。
- 记录实际读取的文件、章节或页码，区分当前依据与历史参考。文件名、日期和修订顺序不自动证明上线状态。
- PDF/DOCX 中的图片表、删除线、改动颜色和批注可能改变规则语义。文字提取不等于完整阅读；必要时视觉核对，裁切或缺失内容列待确认。
- 同一版本内有冲突时列出位置与适用范围，不静默选择。文末笼统声明不能替代规则旁的未知项标记。
- 图片与设计稿只引用实际可用资源。不要把临时授权链接、访问 token、患者资料或无关个人信息复制到交付文档。

## 本地样例索引建议

可在用户自己的工作区记录“类型、文件路径、适用模块、实际读取范围、已知限制”，并保留原件。不要将样例全文写入此公共仓库；样例缺失不妨碍完成已知部分的草稿。
